# Day 1 작업 지시 (2026-10-27)

AGENTS.md 규칙을 먼저 읽고 요약한 뒤, 아래를 순서대로 수행한다.

## 환경 규칙 (중요)
- 파이썬 환경은 사람이 미리 만들어 둔 `.venv`만 사용한다: `.venv\Scripts\python.exe tools/test_director.py ...`
- **가상환경 생성, pip 설치, ensurepip, 시스템 파이썬 점검 등 환경 설정 명령은 실행하지 않는다.** `.venv`가 없거나 깨져 있으면 실행하지 말고 사람에게 알린다.
- 30초 넘게 응답이 없는 명령은 중단하고 보고한다.

1. `.venv\Scripts\python.exe tools/test_director.py fixtures/match_summaries/*.json` 을 실행하고, 결과를 표로 정리한다.
   - 열: 파일 이름 / 성공 여부(OK·FAIL) / 걸린 시간(초) / 입력 토큰 / 출력 토큰
   - 윈도우 PowerShell에서 `*.json` 패턴이 펼쳐지지 않으면 파일을 하나씩 지정해서 실행한다.
2. 실패한 항목이 있으면 원인을 분석하고 해결책을 제안한다.
   - `schemas/`와 `src/shared/` 파일은 고치지 말고 제안만 한다 (사람 승인 필요).
3. 상황이 서로 다른 경기 요약 샘플 6개를 `fixtures/match_summaries/`에 추가한다.
   - 예: 힐러가 없는 팀 / 한 레인만 계속 뚫리는 팀 / 기지 체력 10%로 버틴 팀 / 부활을 많이 한 팀 / 4인 풀파티가 압도한 팀 / 탱커가 일찍 쓰러진 팀
   - 기존 샘플(`wave3_north_breach.json`)과 같은 필드 구조를 따른다.
4. 새 샘플까지 포함해 1번 테스트를 다시 실행하고, 디렉터가 상황마다 다른 웨이브(전술, 레인, 이벤트)를 설계하는지 한두 문장으로 평가한다.
5. `docs/devlog/2026-10-27.md`에 오늘 한 일, 테스트 결과 표, 다음에 할 일을 추가한다.
6. 단계마다 결과가 파일로 남도록 커밋한다(끊겨도 이어서 할 수 있게). 메시지 예: `chore(tools): add fixtures and day1 director test results`

완료 후 사람에게 보고할 것: 결과 표, 실패 원인(있다면), 제안 사항.

# Day 8e 작업 지시 — 지원대끼리 엉켜 하늘로 올라가는 문제 (짧은 작업)

먼저 AGENTS.md와 `docs/devlog/2026-11-04.md` 끝부분(day8d Studio 재측정)을 읽는다. 새 기능은 넣지 않는다. 항목마다 커밋한다.

## 공통 규칙
- 고칠 수 있는 파일: `src/server/Support/SupportSquad.luau`, `SupportSquad.spec.luau`, devlog. 그 밖은 고치지 않는다.
- 환경 설정·패키지 설치 명령은 금지한다. 30초 넘게 멈추는 명령은 중단하고 보고한다.
- Roblox 물리·이동은 lune으로 확인할 수 없다. Studio 확인은 Claude Code가 한다. Studio를 찾거나 실행하는 명령은 쓰지 않는다.

## 배경 (Studio 측정, solo, 사람 1명)
- 맡은 성문 배정은 남·동·서로 올바르게 나뉘었다. 수호자만 도착했다(목표까지 0.7).
- 궁수(x=-2)와 비전술사(x=+2)는 등불 옆에서 4스터드 떨어져 생긴다. 그런데 궁수는 동쪽(+40), 비전술사는 서쪽(-40)으로 가야 해서 정면으로 부딪힌다.
- 두 모델이 1.29스터드 간격으로 엉긴 채 Humanoid 상태가 `Climbing`이 되고, 서로를 타고 계속 올라간다. Y가 376 → 912까지 올라갔고, 수평 위치는 그대로였다.
- 지원대 하나의 네트워크 소유자가 사람 플레이어로 잡혀 있었다. 서버가 움직이는 모델인데 클라이언트가 물리를 맡고 있었다.

## 1. [높음] 지원대끼리 충돌하지 않게
- `PhysicsService`에 충돌 그룹 `"Support"`를 등록한다(이미 있으면 그대로 쓴다). `Support`와 `Support` 사이 충돌을 끈다.
- 지원대 모델의 모든 `BasePart`를 이 그룹에 넣는다. 리스폰으로 다시 만든 모델에도 넣는다.
- 바닥·성벽·적·사람과의 충돌은 그대로 둔다(기본 그룹과는 충돌).

## 2. [높음] 엉켜 올라가는 상태 막기
- 지원대 Humanoid는 `Climbing` 상태를 끈다: `hum:SetStateEnabled(Enum.HumanoidStateType.Climbing, false)`.
- 모델을 만든 직후 `HumanoidRootPart:SetNetworkOwner(nil)`로 서버가 물리를 맡게 한다. `pcall`로 감싸고, 실패하면 warn만 남긴다.
- 안전망: 1초마다 지원대 높이를 본다. 등불 높이보다 30스터드 넘게 높거나 바닥 아래로 떨어지면, 등불 옆 자기 생성 자리로 옮긴다. 옮기고 나서 `[Support] unstuck <이름>`을 남긴다.

## 3. [중간] 생성 위치를 겹치지 않게
- 지원대를 등불 주위 반지름 6스터드 원 위에 서로 다른 각도로 둔다(인원 수로 나눔).
- solo는 웨이브 시작 때 맡은 성문이 정해지므로, 그때 맡은 성문 쪽 각도의 자리에서 출발하게 한다. 텔레포트가 아니라 생성·리스폰 자리를 정하는 규칙으로 한다. 이미 생긴 지원대는 그대로 걸어간다.
- spec: "인원 n명이면 생성 자리 n개가 서로 4스터드 이상 떨어져 있음"(순수 함수로 뺀다).
